# Task Management AI Agent

Manage tasks in plain language. A Gemini-powered assistant picks from three task tools; your tasks are stored locally in `tasks.json`. Use it from a **web UI** (Next.js + shadcn/ui) or a **command-line chat**.

Version 1 is a single-user, single-process, local application.

## Requirements

- Node.js 22 (verified on 22.16.0)
- A Gemini API key from [Google AI Studio](https://aistudio.google.com/). API usage may be billed separately from any consumer subscription, and free-tier quotas are per model.

## Setup

```powershell
npm.cmd install
Copy-Item .env.example .env
```

Edit `.env`:

```text
GEMINI_API_KEY=your-api-key
# Optional
# GEMINI_MODEL=gemini-3.5-flash
# LLM_PROVIDER=gemini
```

> On Windows PowerShell, use `npm.cmd` if script execution is blocked.

## Run

```powershell
npm.cmd run dev:web   # web UI at the address it prints (usually http://localhost:3000; 3001 if 3000 is taken)
npm.cmd run dev       # command-line chat
```

Production build of the web app: `npm.cmd run build` then `npm.cmd run start:web`. Stop any running dev server before building.

## Web UI

- **Tasks** (left on desktop, top on mobile): tabs for All / Open / Overdue / Completed with counts, a Complete button on each row, a detail panel, and a **New task** form that works without the assistant.
- **Assistant** (right on desktop, bottom on mobile): ask in plain language. Replies show chips for what actually ran (for example "Created “X”"), and task lists appear as cards with a status chip and a Complete button.
- **Top bar:** branding on the left; on the right a dark/light toggle and a menu (Light / Dark / System theme, and a read-only Status dialog with provider, model, key state, timezone, storage).
- Chat history is kept in the browser only and cleared on refresh. The last 10 messages are sent with each request so follow-ups like "mark that one as done" work.

## Example requests

- `Create a high-priority task to review the stock report due tomorrow.`
- `Create a task called Submit expense report due 2026-11-01.`
- `Show all open tasks.` / `Show overdue tasks.`
- `Complete the first one.` (after a list) or `Complete task task_<id>.`

## Task rules

- A title is required and cannot be blank. Priority is `low`, `medium` (default) or `high`.
- Due dates are valid `YYYY-MM-DD` dates. Relative dates such as "tomorrow" are resolved by the assistant using the business date; ambiguous dates get a clarifying question.
- Business timezone: `Asia/Kolkata`. An open task is overdue when its due date is earlier than today in that timezone. Completed tasks are never overdue.
- Completing an already-completed task is a no-op that returns the existing task.
- IDs and timestamps are generated by the application, never the model. There is no task deletion in V1.

## HTTP API (used by the UI)

| Route | Purpose |
|-------|---------|
| `GET /api/tasks?status=&overdue=` | List tasks |
| `POST /api/tasks` | Create a task (validated; 400 with a message on bad input) |
| `POST /api/tasks/[id]/complete` | Complete a task (404 if unknown) |
| `POST /api/chat` | `{ message, history }` returns `{ reply, toolCalls }`; rate limited to 10 requests per minute |
| `GET /api/health` | Provider, model, whether a key is configured, timezone |

Chat errors map to: 400 bad input, 503 missing key, 422 agent turn limit, 429 model quota or rate limit, 504 model timeout, 502 other model failure.

## Manual smoke test (needs a key)

1. Ask: "Create a high-priority task to review the stock report due tomorrow." The task appears on the board with a highlight and a "Created" chip.
2. Ask: "Show all open tasks." Cards appear under the reply.
3. Complete a task from a card, then from a board row. Both views update.
4. Ask: "Complete task not-a-real-id." The assistant reports it was not found.
5. Ask: "Create a task with an empty title." The assistant asks for a title; nothing is saved.
6. Ask for something off-topic ("write a python hello world"). The assistant politely declines.
7. Refresh the page and confirm tasks persist. Restart the server and confirm again.
8. Temporarily remove `GEMINI_API_KEY`: a banner explains the assistant is unavailable; the board still works.
9. Toggle dark mode and narrow the window to phone width.

## Safety and limitations

- The model can only call the three registered tools. There is no shell, SQL, filesystem or deletion tool, and all tool arguments are validated in application code.
- The assistant is restricted to task management by its instructions, plus a code-level check that replaces code-block replies. Instruction-level limits are not airtight; the small tool surface is what bounds the impact.
- Agent execution is capped at six model turns, requests time out after 30 seconds, and rate-limit or server errors are retried once.
- Storage is a single JSON file written via a temp file and rename. Corrupt or invalid data is reported and never overwritten. Writes inside the service are serialized, but this is not safe for multiple processes. Run one server only.
- The web app has no authentication and is meant for `localhost`. Do not expose it publicly.
- No recurring tasks, reminders, multi-user support or deletion in V1. Chat memory is not persisted.

## Architecture

The LLM backend is pluggable (`src/llm/`). Gemini is the only provider today; OpenAI can be added by implementing `LlmProvider` and adding a branch in `src/llm/index.ts`.
